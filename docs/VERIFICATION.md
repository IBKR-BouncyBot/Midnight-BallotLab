> Historical baseline report. The text below records the earlier 0.3.0 environment and has not been relabeled as fresh execution. Current compiler, native-runtime, browser, proving and deployment results are in [CONTINUATION_RESULTS.md](CONTINUATION_RESULTS.md). In particular, the missing-native-toolchain limitations below no longer describe the continuation environment.

Reviewed and checked on 3 November 2026.

## Executed successfully

`npm test` ran 95 tests: 95 passed, zero failed, zero skipped. The complete run took about 74 seconds in this build environment (Node.js 24.22.1, Python 3.12.14). These are local protocol and adapter tests, not Midnight execution.

After adding the native browser page, three additional loader tests passed. They cover unavailable builds, initialization failure and readiness ordering, without simulating native arithmetic. The existing synthetic-DOM browser workflow was rerun separately. The repository now contains 98 local tests; the full 95-test run and focused follow-up runs are distinct checks.

The interface also clears verification results when fingerprints or receipts change, clears receipt results when records change, and locks verification inputs during a check. The existing synthetic-DOM workflow covers the browser workflow with the new native-status notice. It does not exercise a native wallet or blockchain client.

The browser and JavaScript CLI now reject duplicate object fields, negative zero and fractional/exponent-form numbers before parsing, matching the Python reference verifier's restrictions on those inputs. The prior generic JavaScript JSON parser could silently accept duplicate fields that Python rejected. The strict JavaScript import path also enforces UTF-8/byte and nesting bounds. Both implementations accept the canonical records generated by this application.

## Important interpretation

The two verifier implementations increase cross-checking coverage. They are not an independent security audit. Both were authored for this prototype and may share design mistakes. No proof of absence of vulnerabilities is claimed.

Expected fingerprints only authenticate a record to the extent that the channel supplying them is trusted. The example record and its adjacent fingerprint file are test fixtures distributed together, not independent trust evidence. Fingerprints are domain-separated canonical JSON hashes, not raw-file checksums.

## Environment limitations established during this build

- No `compact` or `compactc` executable was installed. The supplied compile command was attempted and could not execute.
- Native browser bundling was attempted after a successful baseline static build and stopped because the actual compiler-generated contract was absent. The resulting native manifest remains disabled; no substitute bundle was created.
- Docker was not available.
- A request to the npm package registry returned HTTP 403 in the restricted environment. No network-permission bypass was attempted.
- The eleven admission-starter cases and twenty new native-election cases require the missing runtime and compiler output. **Zero native contract assertions executed.** They are not included in the passing local tests.
- The managed Sites environment did not expose the supported browser control interface. Browser, layout, mobile and camera-scanning QA could not be run. A QR module comparison does not establish real-camera scan reliability.

The native receipt's largest supported QR text (182 ASCII characters) was accepted by the existing QR encoder. This checks encoding capacity only; a native runtime session and real-camera scan were not executed.

## Unverified work

The Compact source has not been compiled, its proofs have not been generated, and no election has been deployed to Midnight. `native-election.compact` now contains native encryption, decryption and tally constraints, but source inspection and abstract algebra tests cannot certify that they compile or execute correctly. The retained `election.compact` is still admission-only. Publishing the browser site is not deploying either contract.

The original browser workflow remains the existing JavaScript protocol. A separate native browser emulator UI and real-runtime bundler are included in source, but native build and browser execution are unverified; the hosted native page keeps its controls disabled. The native SDK client needs real provider/bootstrap configuration and a connected wallet UI; it has not been exercised against a network. Native public snapshots and indexer receipt checks are not independent verification of finalized chain inclusion. Native tests and compiler results must be obtained before extending this prototype toward real proving and transactions.

Independent audits, production-load benchmarks, mobile timing, accessibility testing with assistive technologies and real-world election validation have not been performed. See THREAT_MODEL.md for cryptographic and operational boundaries.
