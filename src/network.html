01 / CONNECT

Real wallet

Choose your test environment.

Use at least 16 characters and three character classes. The SDK encrypts its signing keys in this browser. Do not enter a wallet seed. Configure the wallet's prover to a trusted loopback service such as localhost:6300; this client rejects remote proving destinations.

02 / CONTRACT

Separate deployment

Deploy or join an election.

For a join, obtain both values from a separately authenticated election record. The client checks verifier keys and configuration consistency; it cannot establish honest initial state, maintenance history or chain authenticity from an indexer alone.

Deploy a new synthetic test election

Retain your administrator credential securely before leaving. This page does not export private credentials or custody backups. Deployment alone does not prove key configuration.

The demonstration dealer knows every share. This is not distributed key generation. Two trustees can collude to decrypt individual ballots outside the contract.

03 / VOTER

Encrypted ballot

Enroll, then cast.

Enrollment needs the administrator secret above and must complete before the real network opening time. The voter needs the same private credential when casting. For a joined election, authenticate the meaning of choices 0–2 against its manifest before voting.

An uncertain submission locks further casts in this session so its expected receipt is preserved. Recover it without submitting again. Check transaction status independently before ending the session or attempting a new cast.

Receipt matched indexed ciphertext

QR and JSON identify this ballot, network, contract and configuration. The QR excludes the transaction ID; checking it does not independently verify chain inclusion.

05 / PUBLIC CHECKS

Indexed state

Read with accurate limits.

Exports contain public ciphertexts and trustee contributions, never choices, randomness, private contexts or proof witnesses.
