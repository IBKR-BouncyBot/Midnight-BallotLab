# Isolated local network acceptance

See [current verification status](../../docs/VERIFICATION_STATUS.md) for completed runs, the live Preview browser-wallet attempt, exact versions and remaining limits. Historical results below remain tied to their recorded revisions.

This package exercises the existing generated Compact contract and SDK client on an explicitly selected fresh local `undeployed` chain. It is separate from the browser dependency graph. It does not connect to Preview, Preprod or mainnet. No public-network funds or user wallet credentials are required.

Version 0.6.1 completed the actual [GitHub acceptance run](https://github.com/IBKR-BouncyBot/Midnight-BallotLab/actions/runs/41699843169) at commit `fa94c3a19b4791441208ceae54a121faff2c588b`: 17 accepted transactions, 16 completed proof transactions, five ballots and phase 3 totals `[2,1,2,0,0]` at block 137. The external operator waited for real indexed time beyond the sealed closing deadline, then submitted closing, trustee shares 1 + 3 and finalization. The [public report](../../evidence/2026-11-03/v0.6.1/github/devnet/reports/network-evidence.json) records `automaticCloseAndTally: true` and `onChainSelfExecution: false`. Browser-wallet testing was not part of that Node run; independent chain inclusion remains unverified. The preceding 0.6.0 failure at the fifth ballot remains preserved separately.

Read [the native network guide](../../docs/NATIVE_NETWORK.md) before starting the reviewed loopback node/indexer services and local prover. The public readiness probe is separate from contract acceptance:

```sh
node contracts/devnet/probe.mjs
npm --prefix contracts/devnet ci --ignore-scripts
npm --prefix contracts/devnet run test:runtime
node contracts/devnet/run-election.mjs --isolated-local-devnet
```

The runner is an external scheduled operator by default. `npm --prefix contracts/devnet run scheduled` invokes that same acceptance flow, including deployment and voting, without duplicating transactions. Its reusable `scheduled-operator.mjs` reads the sealed closing deadline from the actual configured native contract, waits for both the real indexer block timestamp and wall clock to pass it, then proves/submits `closeVoting`, two registered trustee contributions and `finalize`. Each step must be confirmed `SucceedEntirely` by the configured local indexer. The contract's deadline, canonical-scalar, frozen-aggregate and two-share checks remain mandatory.

This requires a running Node process, funded local development wallet, prover and indexer. Midnight contracts do not wake themselves at a deadline. The operator holds two synthetic shares in one process under the user's selected centralized local-development custody; it is not independent trustee custody. It accepts only a configured `undeployed` client and a loopback HTTP indexer. GitHub Pages serves the frontend and does not run this operator. An unavailable operator or trustee share can delay tally publication; it cannot make an unproved tally valid. After an uncertain submission, check the public transaction status before another run.

The contract supports two through five active choices, bound by a sealed candidate count and configuration digest. All ciphertexts, aggregates, decryption contributions and totals contain five lanes; inactive choices have zero votes and are explicitly constrained to zero totals. Trustee keys remain a separate three-element vector. The scheduled acceptance scenario uses three active choices, five synthetic voters and final padded totals `[2, 1, 2, 0, 0]`. Public evidence records the selected external-operator mode, actual start/deadline/indexed-close timestamps, accepted transaction identifiers and source hashes; it explicitly denies on-chain self-execution.

Generate the real contract assets with the main contract build first. `stage-runtime.mjs` copies byte-identical application files and generated bindings into `.runtime/`, so their imports resolve the isolated installed dependency graph. No substitute contract or mocked provider is used. The lockfile follows the maintained official example wallet graph: SDK/testkit 4.1.1, wallet SDK 1.2.0, compact-runtime 0.16.0, ledger 8.1.2, onchain runtime 3.1.1 and ZKIR 2.1.1. The ordinary application/browser lockfile retains its separately tested versions.

The runner reads an installed official genesis development fixture directly into memory. It rejects external seed environment variables. Both wallet/testkit loggers are silent before fixture access; library console output is suppressed and only its count retained. No seed, credential, individual selection, randomness, trustee share, proof witness, raw transaction or raw exception is logged. Transient SDK data is encrypted with a fresh in-memory password in a temporary directory, which the runner removes during cleanup. The local genesis wallet is not a production identity.

Allow approximately thirteen to sixteen minutes after wallet synchronization. The election opens four minutes after setup begins and closes eight minutes later. The voting window allows for five sequential native ballot proofs and confirmations; the earlier four-minute window ended with four accepted ballots and an unconfirmed fifth submission in the retained 0.6.0 CI failure. The runner waits for actual indexed and wall-clock time. It deploys, configures the keys, enrolls five synthetic members, opens, casts five ballots, closes, submits trustee contributions 1 and 3, and finalizes. Every counted acceptance requires the configured indexer to report `SucceedEntirely`. Receipt and final-tally comparisons use the actual generated contract's public state. Negative tests separately establish that invalid selections, duplicate credentials, a wrong trustee share and changed totals are rejected before proving/submission.

Public evidence is written incrementally to `artifacts/local-devnet/network-evidence.json`, including dependency/source hashes, transaction IDs, heights and explicit confirmation limits. Events include wall-clock timestamps; a failure records the public indexer clock when available and whether the closing deadline has passed. That clock observation does not establish the rejection reason. `scheduledTallyStarted` distinguishes reaching the external tally operator from failing during setup or voting. A failed or interrupted submission may have an uncertain outcome; inspect the recorded public transaction status before another attempt. The runner does not automatically retry a submitted election operation. Its final replay attempt reports only the observed submission-pipeline result, without inventing an independent chain-rejection claim.

The `ws` dependency is pinned to 8.22.1 after the initial audit identified vulnerable 8.20.0. The remaining eight moderate audit findings are in testkit's transitive container/archive dependency graph. This runner does not call those helpers, but they remain installed; no incompatible major override was applied to hide the findings. The separately installed browser/application graph has its own audit result.

A successful run establishes acceptance on this local chain through its configured indexer. This Node runner does not validate a browser extension connection, a public-network deployment, independent chain inclusion or election certification; the local Lace election was tested separately. GitHub Pages hosts the static frontend and provides none of the local services.
