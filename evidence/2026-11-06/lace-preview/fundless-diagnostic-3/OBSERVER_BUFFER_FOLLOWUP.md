# Observer buffer follow-up

The retained run produced a genuine 2,933-byte Lace API `openVoting` proof and discovered the exact offscreen page and worker. Its strict resource gate failed with the combined category `prover-resource-body-unavailable-or-invalid`. No raw body or protocol error was retained; this report therefore cannot establish which body failure occurred.

Source review found a concrete insufficient buffer bound in the observer. The pinned WASM is 3,413,037 bytes, but its base64 representation is 4,550,716 characters, already larger than the previous 4,194,304-byte per-resource buffer. Chromium 156.0.8078.4 [`DecodeDataToContent`, lines 179–188](https://github.com/chromium/chromium/blob/156.0.8078.4/third_party/blink/renderer/core/inspector/network_resources_data.cc#L179) converts the stored data to content. [`MaybeDecodeDataToContent`, lines 314–324](https://github.com/chromium/chromium/blob/156.0.8078.4/third_party/blink/renderer/core/inspector/network_resources_data.cc#L314) compares that content's character-storage size against the per-resource limit and evicts oversized content. [`GetResponseBody`, lines 2533–2535](https://github.com/chromium/chromium/blob/156.0.8078.4/third_party/blink/renderer/core/inspector/inspector_network_agent.cc#L2533) then rejects evicted content.

The correction bounds each resource at `4,550,716 × 2 + 65,536 = 9,166,968` bytes, allowing a possible two-byte string representation, and total inspector storage at 18,333,936 bytes. The incoming message limit remains 6 MiB of characters. Successful verification still requires base64 encoding, canonical decoding, exactly 3,413,037 decoded bytes and the original pinned SHA-256. No file read or substitute request can become a runtime observation.

Fixed, locally branded failure categories now distinguish retrieval timeout, known inspector eviction, missing resource/data, other protocol rejection, unexpected encoding, encoded/decoded length and hash mismatches. Raw protocol text, body contents and unexpected hashes remain excluded from reports.

Six focused boundary tests passed, including a genuine nested-message parse of a body exceeding 4 MiB which must fail the real hash check for substituted bytes. These are transport/validation tests, not a new wallet proof or successful resource observation. The original failed evidence is unchanged; a fresh diagnostic is still required.
